# 채널 close 완료 신호 벤치마크

## 변경과 안전성

현재 구현은 실행마다 `done chan struct{}`를 만들고 중복 호출자가
샤드 mutex를 놓은 뒤 `<-c.done`으로 기다립니다. 생산자만 결과·오류를 확정하고
공통 완료 defer에서 정확히 한 번 `close(c.done)`합니다.

- 채널은 map 등록 전에 생성합니다. 값을 보내지 않고 닫기만 합니다.
- 닫힘은 현재 대기자를 모두 해제하고, 이후 수신도 즉시 반환시킵니다.
- 닫힘을 관측한 수신자에게 이전 결과 쓰기가 동기화되므로 결과용 추가 락은 없습니다.
- 정상 반환·error·panic·runtime.Goexit 경로 모두 내부 완료 신호를 닫습니다.
- 완료 후 샤드 mutex 재획득이 없으며, 실행 객체와 채널은 재사용하지 않습니다.
- 기본 255개 샤딩·maphash·공개 API·Forget 교체 보호는 유지합니다.
- **DoChan의 공개 결과 채널은 닫지 않습니다.** 내부 done 채널과 별개입니다.
  기존대로 한 번 결과를 보내며, panic/Goexit의 공개 동작도 유지합니다.

이전 WaitGroup 및 Cond 구현은 테스트 전용 `*_baseline_test.go`에 보존했습니다.
프로덕션 패키지는 이 파일들을 포함하지 않습니다. 과거 측정은
[BENCHMARKS-WAITGROUP.md](BENCHMARKS-WAITGROUP.md)와
[BENCHMARKS-COND.md](BENCHMARKS-COND.md)에 보존합니다.
아래 수치는 **네 구현을 같은 실행에서 다시 측정**한 결과입니다.

## 범위·병합량·할당: 주요 케이스 (8)

범위는 실제 5개 표본의 최소–최대이며 신뢰구간이 아닙니다.
backend/op는 호출 하나당 생산자 실행 횟수, shared/op는 공유 결과를 받은 호출 비율입니다.
최초 호출자도 Shared=true일 수 있어 두 비율의 합이 1인 관계는 아닙니다.

| 케이스 | Channel 범위 | WG 범위 | backend/op Ch / WG | shared/op Ch / WG | B/op Ch / WG |
|---|---:|---:|---:|---:|---:|
| Serial / 짧은 키 | 174.3–201.7 | 119.7–141.2 | — / — | — / — | 192 / 80 |
| Do / 독립 키, 즉시 반환 | 98.2–135.3 | 49.83–57 | 1 / 1 | 0 / 0 | 192 / 80 |
| Do / 단일 키, 즉시 반환 | 620.5–744.7 | 636.8–659.6 | 0.6684 / 0.6669 | 0.4982 / 0.5047 | 128 / 53 |
| Do / 단일 키, Gosched | 633.5–685.8 | 694.2–856.7 | 0.2152 / 0.2294 | 0.9873 / 0.9797 | 41 / 18 |
| Do / 16개 키 순환, Gosched | 486–540 | 524.8–565.6 | 0.4793 / 0.5191 | 0.7968 / 0.759 | 92 / 41 |
| Do / 독립 키, CPU 작업 | 327–383.2 | 273.2–368.3 | 1 / 1 | 0 / 0 | 200 / 88 |
| Do / 단일 키, CPU 작업 | 574.5–636.1 | 868.1–1031 | 0.1774 / 0.2096 | 0.9811 / 0.968 | 35 / 18 |
| DoChan / 단일 키, Gosched | 766–834 | 666.4–856.5 | 0.2405 / 0.2444 | 0.9716 / 0.9693 | 238 / 212 |

중복 없는 짧은 Do는 **Channel 192 B/op / 2 allocs/op**, WG·Cond·x/sync는
80 B/op / 1 alloc/op입니다. 내부 채널 때문에 생산자 실행마다 **112 B와 할당 1회**가
추가됐습니다. 채널은 런타임 내부 동기화를 사용하므로 lock-free가 아닙니다.

- 독립 CPU 작업: Channel 200 B / 3회, 나머지 88 B / 2회 (interface boxing 포함).
- 독립 DoChan: Channel 424 B / 6회, WG·Cond 312 B / 5회, x/sync 296 B / 5회.
  공개 결과 채널에 더해 내부 완료 채널을 만들기 때문입니다.
- ColdGroup: Channel 16,784 B / 260회, WG·Cond 16,672 B / 259회,
  x/sync 352 B / 4회. Group을 요청마다 만들지 말고 재사용해야 합니다.
- 병합 케이스의 allocs/op 정수 표시는 분수 할당량을 숨길 수 있습니다.
  0으로 표시되어도 실제 할당이 없다는 뜻은 아닙니다.

## 해석과 한계

1. **안전한 일회성 완료 신호로 사용할 수 있습니다.** 현재/늦은/반복 수신과
   예외 완료를 검증했고, 완료된 대기자의 샤드 재잠금은 없습니다.
   다만 이 재잠금 제거는 WG에서도 이미 제공하던 성질입니다.
2. **겹침이 많은 핫 키 Do에는 개선이 관측됐습니다.**
   Gosched 중앙값은 WG 대비 약 13.4%, CPU 작업은 약 33.3% 낮았습니다.
   두 경우 backend/op도 낮아져 병합량이 증가했으므로, 그 차이를 순수한
   close 대 Done의 깨우기 비용 차이라고 단정할 수 없습니다.
3. **독립 키·짧은 작업에는 채널 할당 비용이 부담입니다.**
   8워커 독립 키 즉시 반환은 107.2 vs 50.96 ns/op로 약 2.1배 느렸고,
   짧은 직렬 호출은 186.5 vs 136.0 ns/op로 비용이 약 37% 늘었습니다.
   많은 키의 경합 절감은 남아 있지만, WG 대비 범용 성능 개선은 아닙니다.
4. DoChan은 공개 결과 채널로 기다리므로 내부 신호 채널의 수신 이점을
   직접 받지 않으며 추가 생성·close 비용이 있습니다.
5. 개발 환경에서 순차 측정했고 전력 모드·주파수·백그라운드 부하를
   고정하지 않았습니다. 작은 차이·겹치는 범위·실행 순서·해시 배치의 영향을
   고려해야 합니다. benchstat 미설치로 통계적 유의성 검정은 하지 않았습니다.
6. 마이크로벤치마크로 실제 I/O·지연 분포·고카디널리티·장시간 부하를
   검증하지 않았습니다. 새 취소 API를 추가한 것도 아닙니다.

사용자 요청대로 현재 구현은 채널 버전으로 유지합니다. 이번 결과는
**완료 프로토콜은 단순해지고 일부 핫 키는 좋아졌지만, 할당과 독립 키 성능은
나빠졌다**는 교환 조건을 보여줍니다. 기본 구현 선택은 실제 키 분포와 작업 길이를
기준으로 판단해야 합니다.
